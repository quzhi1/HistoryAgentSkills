# 小红书浏览器发布

把 `outputs/xhs/<段子名>/` 下已经渲染好的 PNG 和上一轮定稿的文案，填进小红书创作服务平台的
发布页。**只填表，不替用户做决定**：内容来自上一轮，发布与否由用户点头。

## 红线

- **发布前先对一遍**：填完截图，复述标题、正文、图片张数、话题、两个声明的状态，
  再点发布。笔记发出去之后还能改能删，所以这是对账，不是请示；用户叫停或要存草稿
  就点「暂存离开」。
- **不登录**。不填手机号、不填验证码、不点「发送验证码」。页面跳到登录页就停下来告诉用户，
  等他自己登完再继续。
- **不改内容**。标题、正文、话题一字不改地照搬上一轮的定稿。要改文案回 `xiaohongshu-cards`，
  要改史料回 `random-history-anecdote` 或根目录 `SKILL.md`。
- **不删限定语**。「今地未能确认」「（四库本）」「（推断）」这类话在正文里照留，不为了好看删。
- **不自己配图**。只传 `outputs/xhs/` 下这一轮生成的卡片。

## 前置

1. 卡片已经渲染好，在 `outputs/xhs/<段子名>/`，文件名 `01-cover.png`、`02-body.png` …… 顺序即上传顺序。
2. 文案已经定稿：标题 ≤20 字、正文 ≤800 字、话题 3–5 个。没有就先跑 `xiaohongshu-cards`。

## 先搞清楚是哪个站、哪个标签

小红书创作平台有两个域名，账号不通用：国际站 `creator.rednote.com`，国内站
`creator.xiaohongshu.com`。**登录态跟着域名走**——在 rednote 登录了，打开 xiaohongshu
照样跳登录页。别凭印象选，先看用户实际开着哪个：

```
mcp__Control_Chrome__list_tabs      # 能列出用户真实 Chrome 的所有标签，不受标签组限制
```

## 两套浏览器工具，用哪套

| | Claude in Chrome（扩展） | Control_Chrome |
| --- | --- | --- |
| 能看到的标签 | 只有自己标签组里的 | 用户真实 Chrome 的全部 |
| 能做的事 | 真实点击、打字、`file_upload` | 读页面 / 执行 JS（无原生点击） |
| 前提 | 标签要在它的组里 | Chrome 要开 JS-from-Apple-Events |

**默认走扩展**：让用户把草稿标签拖进 Claude 的标签组（或右键标签 → 加入该标签组），
之后点击、打字、传图都是真实操作，最稳。

Control_Chrome 只作兜底。它的 `get_page_content` 和 `execute_javascript` 如果报
「Google Chrome is not running」，**不是 Chrome 没开**，是 Chrome 的
View → Developer → Allow JavaScript from Apple Events 没勾（这个开关只有用户能点）。
勾上之后能读页面、能注入 JS，但没有原生点击，传图得自己用 DataTransfer 造 File 塞进
file input，React 受控输入还要走 native setter + 派发 input 事件——能用，但脆，
能走扩展就别走这条。

跳到 `/login?...redirectReason=401` 多半是**域名选错了**（在另一个站登录着），先换域名再试；
确实没登录就停下告诉用户，不要自己登。

## 流程

1. 进发布页（上面查到的那个域名），切到「上传图文」那个 tab（图文笔记，不是视频）。
2. `find` 找文件输入框（找 "file input" / "上传图片"）。**不要点上传按钮**——那会弹出
   系统文件选择框，Claude 看不见也点不了。拿到 ref 后用 `file_upload` 直接传。
3. 一次把全部 PNG 按文件名顺序传进去。单次合计要 <10MB；本项目的卡片每张 50–200KB，
   18 张也就两三 MB，一次传得完。
4. 截图确认缩略图数量和顺序对得上。少了就补传少的那几张，顺序乱了在页面上拖回来。
5. 填标题和正文。正文用 `form_input` 或点进去 `type`，富文本框 `form_input` 可能不生效，
   不生效就改用点击 + type。
6. 话题：在正文末尾打 `#` 会弹下拉，**必须从下拉里点选**，光打字出来的只是普通文本，不成标签。
   一个一个来，每个都确认选中了。
7. **内容设置**，只动这两项，别的一律不碰：
   - **原创声明**：打开。会弹一个权益说明框，要勾「我已阅读并同意《原创声明须知》」
     再点「声明原创」，否则开关弹回去。
   - **内容类型声明**：下拉选「笔记含AI合成内容」。
   「允许正文复制」「公开可见」是平台默认开着的，不是我们勾的，别去关；
   「虚构演绎」「营销广告」「内容来源声明」「添加地点」「群聊」「定时发布」都不要动。
8. 截图整页对一遍，然后点「发布」。出现「发布成功」页即可。

## 发布之后：等审核 + 验证外部可见

发完不算完。新笔记会进**审核中**，这期间等同于 shadow ban——作者自己看得见，
外面看不见。必须盯到审核通过，并且用**未登录**的身份确认真能打开，才算交付。

1. 去 `https://creator.rednote.com/new/note-manager`，新笔记会带「审核中」角标。
   审核期间卡片上的分享/权限图标是灰的，悬停提示「笔记审核中，暂不可设置」，
   **这时候拿不到笔记链接**，别在这上面耗。
2. 隔一段时间回来刷新看角标（后台 `sleep` 再回来查，别在前台空转）。
   角标从「审核中」变成已发布（或进「已发布」分类）才算过。变成「未通过」就截图告诉用户，
   不要自己改内容重发。
3. 过审后从卡片上的分享/权限入口取笔记链接。
4. **用未登录的浏览器验证**：用 Claude 自带的浏览器面板（`mcp__Claude_Browser__*`）打开那个链接
   ——它和用户的 Chrome 完全隔离，天然是未登录态，正好当外部读者。
   确认标题、封面、正文都出得来，不是登录墙也不是 404。
   注意小红书站内**搜索**对未登录用户是关的（只会显示「登录后查看搜索结果」），
   所以只能直接开链接验证，不要用搜索来判断。
5. 把结果告诉用户：链接 + 过审时间 + 未登录可见已确认。

## 页面实况（2026-10 在 creator.rednote.com 实测）

改版就会过期，对不上以页面为准，但别一上来就当它错的。

- 扩展的标签组就在用户自己的 Chrome 里，**登录态直接通用**，不用登也不用传 cookie。
  之前以为要登录，是因为域名敲错了（rednote 的账号打不开 xiaohongshu）。
- 进去默认停在「上传视频」，要先点「上传图文」。
- 文件输入是个 `button type="file"` 元素，`read_page --filter all` 能看到；
  拿它的 ref 喂 `file_upload`，15 张 2.2MB 一次传完，页面显示「15/18」。
- **标题**是真的 `textbox`，`form_input` 可以直接灌。
- **正文是 contenteditable 的 DIV**，`form_input` 会报
  `Element type "DIV" is not a supported form input`——改成点进去再 `type`。
  `type` 的字符串里 `\n` 能正常换段，整段几百字一次打进去没问题。
- 正文计数器写的是 **/1000**，不是 800。
- **话题**：在正文末尾 `type` 一个 `#关键词`，等 2–3 秒浮出一行候选（没有现成话题时
  右边是「新建话题」），**必须点那一行**才会变成蓝色话题链接。一个一个来，
  每点完一个再打下一个；下拉的位置每次都在动，别套用上一次的坐标。

## 定位控件

小红书改版频繁，**不要在本文件里记死坐标或 CSS 选择器**。每次都用 `find` 按自然语言找：
"上传图文 tab"、"标题输入框"、"正文编辑器"、"发布按钮"、"暂存离开按钮"。
找不到就截图问用户，不要凭猜测乱点——点错可能直接发出去。

## 交付

发布成功后给出笔记链接（能拿到的话）；只存了草稿就说明存在哪、下次从哪继续。
